## Built
- **Standard body (controller 1).** No case-study body template existed anywhere in the code (T2 drafted an empty body; nothing else creates a case study body). I added `CASE_STUDY_BODY_TEMPLATE` in `src/modules/casefile/body.ts` (exported through `casefile/client`): only the heading the app lint requires, `## What would prove me wrong`, with no words of his or the machine's. `draftCaseStudy` now stores it as the first revision's body; a refresh carries his body as before. A body of headings alone is not shown to readers (`bodyBlocks` in `showcase/case-study.ts` returns nothing), so a bare heading never reaches the page. The app lint is unchanged.
- **Structure check for a ledger case.** `fileProblems` (shared by the checklist and `publishCheckedAction`) returned the facts-sheet and "- T1:" problems for any case study, which would have made a ledger case unpublishable from the desk (`FileStructureError`). It now returns none for a record-carrying case study; the lint still asks for the heading and the gate for the rest.
- **Frozen date (controller 2).** `ledgerStatus(deps, itemId)` in `src/modules/cases/service.ts` returns `{ differs, figuresTo, dateOut, frozen }` (`frozen` = the item is public and its Figures to is not the ledger's date, which is exactly when the gate says `case_figures_to`). `LedgerRecordPanel` says the way out in plain words only when `frozen`, and offers no Refresh button in that state (a refresh the gate would refuse is not offered). A refresh whose record already matches but whose date was behind now moves the date and reports a change.
- **No facts sheet (controller 3).** For a ledger case `loadEditor` skips the staged figures, readings, provenance and the documents button; `sheet` is null (no facts editor, no text sheet); `RevisionEditor` takes `ledgerCase` for its own help text.
- **Idea page.** `src/components/desk/private/ledger/idea-case-block.tsx` (closed ideas only; spec s33.8 sentences; the draft button disables itself while it runs) wired in `src/app/desk/ledger/[ideaId]/page.tsx` through `loadCaseBlock`. States: open and withdrawn nothing; no lesson; exit not fixed; ready (switch on or off); draft or public (link to the item); could not read (one sentence, no button).
- **Item page.** `src/components/desk/private/case/ledger-record-panel.tsx`: "From the ledger (sealed; cannot be edited)", the machine's dates, whether a chart is part of the record, then each entry through the public `CaseEntry` component (his words as text). "Refresh from the ledger" only when the record differs or a private item's date is behind. `src/app/desk/items/[id]/ledger-case.ts` tells a ledger case by the key, as the gate does.
- **Checklist line.** `previewGate` takes `ledgerCase: { switches }` and adds "Case studies from the ledger: On|Off (site owner). Chart: on|off." (off is a failing line, unreadable is a hand line) and describes the structure row for a ledger case as "Body and ledger record only; no facts sheet." The desk has no file-view preview to redirect (the item page previews the body only), so nothing else changed in `preview.ts`.
- **Hint (D44).** The lint core is not browser-safe (`hash.ts` is server-only), so `lintWords` in `src/modules/compliance/words.ts` (client-safe, same lexicon, same folding, rules 1 and 2, no hash) is exported from `compliance/client`. `SealedWordsHint` rides on the new idea, change of period, close and lesson (never note, size change, withdrawal). It never blocks a submit.
- Supporting: `src/modules/cases/client.ts` (types for the screens), `src/modules/cases/desk.ts` (`loadCaseBlock`, `loadLedgerView`), `recordEntryViews` exported from showcase, `src/test/fakes/cases-repo.ts` (the cases fake, moved out of `service.test.ts` to keep it under 300 lines; the new status tests are in `service.status.test.ts`). ## Concerns for the controller
1. **No standard template existed.** Controller note 1 said to reuse "the template other case studies use"; there is none in the code. I created the minimal one (the single required heading). A richer template would need his words for the headings.
2. **No Refresh button while frozen.** I hide it (the sentence says Unpublish first), so Unpublish, Refresh, Publish works in that order; the plan's text allowed a Refresh while public that the gate would then refuse. Say if you want the button back.
3. **Figures to is still an editable field on a private ledger case** (Details). A hand-typed date that differs from the ledger's is flagged by the "not the ledger's date" line and refused by the gate; making the field read-only for this kind is a small follow-up I did not do.
4. **A case with only the template heading shows nothing under "Looking back"** on the public page; with text under it, the heading shows with it. "What would prove me wrong" under "Looking back" reads oddly for a closed case if he writes under it; his call.
5. **`publishCheckedAction` changed behaviour** through `fileProblems` (a ledger case no longer throws the facts-structure error). Task 5's e2e is the first to publish a real one through it. For the runbook (note 4): older passed revisions stay readable until Unpublish, and the Unpublish, Refresh, Publish order belongs in the checklist line that covers publishing.
