**Goal:** Aksh saves other people's YouTube videos, web pages and newsletter issues with one capture line, attaches each to companies and concepts with his own note, and can show chosen ones on a public company file, through the same gate as everything else, with the thumbnail served from our own storage. Letters and the own-channel video flow are switched off and out of view, reversibly.

**Architecture:** new table `source_links` (link + machine data, private) with company and concept join tables, a private thumbnail bucket, and one anon view `public_studied`; the public choice is `structured.studied` in the company file's revision, checked by a new branch of `private.distribution_gate_failures` (rule 14, policy v1.3). New module `src/modules/sources/` (url key, outbound reads through `safeFetch`, service, actions, steps glue). One public route `/media/studied/[file]`. A code switch `src/lib/features.ts` hides letters and own videos.

**Spec:** `docs/specs/2026-10-16-sources-design.md` (s0-s13; decisions D98-D113 in s12; copy in s13). **Rules:** `docs/compliance/publishing-rules.md`, v1.1, v1.2 and the new `publishing-rules-v1.3-addendum.md` (rule 14). **Questions:** Q53-Q56.

## Global constraints
- **Nothing outbound in a test or at deploy.** Unit tests inject `resolve` and `transport` from `src/modules/documents/safe-fetch-fakes.ts`; nothing in `src/modules/sources` imports `httpsTransport` or `systemResolver` (graph test); real deps come only from `createLinkFetchDeps(env)`. E2E runs with `LLM_ADAPTER=fixture` (fixture sites), and a Playwright route guard fails any browser request to a host other than the app.
- **One publish path.** No change to `private.is_public_item`, `public_items`, `public_item_revisions`, item or revision policies, `/api/health`, `HEALTH_RULES`. Anon gains exactly `public_studied` (select), the column grants and row policy it needs, and the storage read policy on `source-thumbs`.
- **His words and the machine never share a field.** His: the link's private `note`, the entry `note`, change reasons. Machine: `title`, `site_name`, `channel_url`, thumbnail, dates, problem codes. Nothing re-words his text; the machine never writes a change reason. No LLM, OCR or transcriber port in `src/modules/sources`.
- **Public boundary:** `src/app/(public)/**`, `src/app/media/**`, `src/modules/showcase/**` import no desk module, no `@/modules/sources` except its pure `public` entry, no service or cookie client (extend `isolation.test.ts`). No UUID in any derived output (the shared scan).
- **Naming:** the casefile's existing `sources` key (S1..S30) is untouched; the new key is `studied`, the new table `source_links`, the screens say "Sources" on the desk and "Other people's work I studied" in public.
- Wording: plain; never "proof", "verified", "buy", "sell" in our own copy; every new string listed in the task report as pending approval (spec s13).
- Migrations local only; never edit one after it reaches hosted; `pnpm db:types` after Task 2. Supabase CLI via `pnpm supabase`. Files under 300 lines (the restated `publish_revision` may reach about 210). TDD: see the failing test fail first. Never two implementers at once. `defenso guard_code` on Tasks 2 and 3 if its server answers; otherwise the opus reviews stand in. No new dependency.
