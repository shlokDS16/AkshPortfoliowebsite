# Stack pitfalls (2026-10-04)

Flags: [C] contradicts conventional wisdom, [U] unverified or third-party only.

## 1. Ingestion queue on Hobby
- Cron: once/day, fires anywhere within the hour, no retry on failure, best-effort, may duplicate. Needs a lock plus idempotent reconcile-style handler. https://vercel.com/docs/cron-jobs/manage-cron-jobs
- Functions: 300 s hard cap on Hobby (800 s/1800 s are Pro). LLM wait time is not Active CPU. https://vercel.com/docs/functions/limitations
- [C] Hobby is not queue-less. Vercel Queues (beta, all plans, first 1M ops free, TTL up to 7 days, 100 MB messages). Default visibility timeout is 60 s: raise it above your LLM call time or messages redeliver mid-job. At-least-once, so idempotent handlers. https://vercel.com/docs/queues/pricing
- [C] Vercel Workflows run on Hobby: 50k events/month, 1 GB written, 1-day state retention, no run-duration limit, each step bounded by the 300 s function cap. https://vercel.com/docs/workflows/pricing
- QStash free: 1,000 msgs/day [U]. https://agentdeals.dev/vendor/upstash
- Supabase Edge Functions free: 150 s wall clock (shorter than Vercel), 2 s CPU excluding I/O. https://supabase.com/docs/guides/functions/limits. pg_net default timeout 2 s, Cron UI 5 s. https://github.com/orgs/supabase/discussions/37574
- Plain DB queue: `FOR UPDATE SKIP LOCKED` with no lease leaves rows stuck in "processing" after a 300 s timeout. Add `locked_until` and a reaper step. https://github.com/ancore-org/ancore/issues/1418
- Simplest fit: daily cron claims N jobs with leases, processes until ~250 s, exits.

## 2. RLS, keys, SSR auth
- Views bypass RLS unless `security_invoker = true`. https://dev.to/datadeer/postgres-views-the-hidden-security-gotcha-in-supabase-ckd
- Never gate admin on `user_metadata` (user-editable); use `app_metadata` or an admin table. UPDATE policy with only USING lets rows be reassigned: add WITH CHECK. https://dev.to/mason_roy/6-supabase-rls-policies-that-pass-code-review-and-still-leak-data-1hi5
- Legacy anon/service_role keys retire by end of 2026; use sb_publishable/sb_secret (secret key independently rotatable, blocked in browsers). Rotating a legacy key means rotating the JWT secret and signing everyone out. https://supabase.com/docs/guides/getting-started/api-keys
- Server authz: getClaims() or getUser(), never getSession(). Apply the Cache-Control headers from `setAll`, else a CDN can serve one user's session to another. https://supabase.com/docs/guides/auth/server-side/nextjs
- proxy.ts: `NextResponse.redirect()` after a refresh drops the refreshed cookies (logout loops); exclude cron/webhook routes from the matcher; proxy is not an authorization layer, re-check in every route and action. https://dev.to/daniel_pertu/next-16-renamed-middleware-to-proxy-and-our-whole-auth-boundary-is-one-allowlist-37eh

## 3. Free-tier pause and size
- Pauses after ~7 days without activity; one-click restore only for 90 days. https://tellmewhendown.com/blog/why-supabase-pauses-your-project [U, not official]
- [C] Conflicting reports on whether a read ping counts; one source says writes are now required. https://shadhujan.medium.com/how-to-keep-supabase-free-tier-projects-active-d60fd4a17263 [U]. Safe: daily cron does a tiny UPDATE on a heartbeat row. Vercel does not retry a failed cron, so also keep a second pinger.
- Over 500 MB database size (indexes and extensions count, WAL does not) the project goes read-only. https://supabase.com/docs/guides/platform/database-size
- Sizing (my arithmetic, [U]): vector(384) = 1,544 B/row; HNSW about 1.9 GB per 1M rows at 384-d (https://www.dbi-services.com/blog/pgvector-a-guide-for-dba-part-2-indexes-update-march-2026/ shows indexes can exceed table size). About 3.5 KB per chunk plus chunk text: roughly 90k chunks at 384-d, 35k at 1536-d.
- At Groq's 70-100 pages/day, ~17 KB/page (text, JSON, 2 chunks) reaches 500 MB in about a year. Keep PDFs in Storage (1 GB), skip HNSW below ~10k chunks.

## 4. Groq
- 8k TPM, 200k TPD, org-level. 429 carries `retry-after`; `x-ratelimit-remaining-tokens` is per-minute, requests header is per-day. Cached tokens are free. https://console.groq.com/docs/rate-limits
- Reasoning tokens count: a 40-headline batch hit ~7k, every second batch 429'd, and LiteLLM's two quick retries gave up. Honour retry-after, lower reasoning_effort, shrink batches. https://github.com/sbOogway/manc/issues/45
- Whether max_tokens is reserved against TPM is not confirmed in docs [U]; set it tight anyway.
- Budget in tokens, not calls: ledger table, stop near 180k TPD, resume next cron.

## 5. Next.js 16
- Node >=20.9, TS >=5.1; sync cookies/headers/params removed; revalidateTag needs a second arg; `next lint` gone; parallel slots need default.js; image defaults changed (qualities [75], 4 h TTL). Turbopack default: `next build` fails if any webpack config exists, even plugin-injected; escape hatch `--webpack`. https://nextjs.org/docs/app/guides/upgrading/version-16
- [C] cacheComponents is not a rename: enabling it makes uncached data outside Suspense a build error, and cookies() inside 'use cache' fails. With Supabase cookie auth, leave it off at first. Same page
- 16.3.0 Turbopack: prerendered HTML referencing CSS chunks that 404 on Vercel (Hobby user, no confirmed fix; unknown if 16.3.8 fixes it). https://community.vercel.com/t/turbopack-next-js-16-3-prerendered-html-references-css-chunk-that-404s/48100. 16.2 Turbopack OOM on Vercel builds. https://qasimcode.com/blog/2026-05-17-nextjs-16-turbopack-build-oom-vercel. Mitigate: smoke-test a preview deploy, keep `--webpack` fallback, or disable `turbopackFileSystemCacheForBuild`.
