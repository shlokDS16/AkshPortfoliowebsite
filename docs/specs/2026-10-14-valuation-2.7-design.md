# 2.7 Valuation models: upload an XLSX, confirm its cells, try scenarios (PRIVATE desk only)

Status: approved by delegation 2026-10-14 (Shlok asked for 2.7 by name and delegated every choice; decisions D1-D20 below,
each with its cost if wrong). Author: desk-architect. Built by `docs/plans/2026-10-14-valuation-2.7.md`.
Binding parents: ADR-001 s3 (HyperFormula GPLv3 accepted), s4 (module `valuation`), s8.4 (interactive models private in v1);
`docs/compliance/publishing-rules.md` rule 9; Phase 2 spec s4, s6.2, s7, s8, s10 and ADR-004 (documents, jobs, trays);
tooling landscape s2. No new ADR: this spec stays inside ADR-001's shape.

## 1. Problem
Aksh builds his valuation in Excel. Today the desk cannot hold it: the workbook lives on his laptop, its assumptions are
undated, and he cannot ask "what if the cost of capital is one point higher?" from his phone. He needs to drop the workbook
in the inbox, say which cells are his assumptions and which are the results, and then move the assumptions and see the
results move, without ever overwriting the workbook and without anything leaving the private desk.

## 2. Current state (what is reused)
- Upload: drop bar -> `startUploadAction` -> browser uploads straight to Storage with a signed upload URL (`uploadToSignedUrl`;
  the file never passes through a Vercel Function, so the 4.5 MB body limit does not apply) -> `finishUploadAction` checks
  the stored object, activates the document, queues the job's first step and schedules `after()` drain
  (`src/modules/documents/upload.ts`, `src/modules/ingestion/actions/upload.ts`).
- Jobs: `jobs` / `job_steps` with lease, passes, `needs_attention`, four pumps (Phase 2 spec s8). Trays are derived (`trays.ts`).
- Hardened zip reading: `src/lib/providers/zip-one.ts` (bounds declared and real inflated size, refuses zip64, encryption,
  odd methods; never uses entry names as paths). It reads exactly one entry; an XLSX has many, so the pattern is reused
  in a new multi-entry scanner and `zip-one.ts` is left untouched.
- Desk components: `@/components/ui/table` (`Table`, `TH numeric`, `TD`), `block-header`, `as-of`, `stat-tile`,
  `empty-state`, the inbox `document-card`, `needs-attention`. The public `scenario-table.tsx` already refuses value fields
  (rule 9) and is not touched.

## 4. Security of untrusted workbooks
The workbook is treated as hostile even though Aksh uploads it (files arrive from brokers and email).
1. **Accepted:** `.xlsx` only, at most **10 MB** (`XLSX_MAX_BYTES`). Refused at the drop bar and again on the stored object:
   `.xlsm`, `.xlsb`, `.xls`, `.ods`, `.csv`. The browser often reports an XLSX as `""` or `application/octet-stream`
   (Windows without Office), so the client sets the official type
   `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` from the extension; the job checks magic bytes.
2. **Magic bytes:** must start `50 4B 03 04` (zip). `D0 CF 11 E0` (an OLE file: a password-protected workbook or an old
   `.xls`) is refused with "This workbook is password-protected or in the old .xls format. Save it as .xlsx without a
   password and upload again."
3. **Zip scan before SheetJS sees a byte** (`zip-scan.ts`, the `zip-one.ts` rules for every entry): at most 1,000 entries;
   no zip64, split archives, encryption, or methods other than stored/deflate; each entry's declared size at most 25 MB and
   the sum at most 60 MB; every entry is then really inflated with `maxOutputLength = declared size` and must match its size
   and CRC, so a lying header cannot get past (a zip bomb stops at 60 MB). Entry names are only compared with fixed strings,
   never used as paths.
4. **Refused parts (no macros, no outside links):** any `xl/vbaProject.bin`, anything under `xl/activeX/`, `xl/externalLinks/`
   or `xl/connections.xml`, or a `[Content_Types].xml` that declares `sheet.macroEnabled`. Messages name the fix in Excel
   ("Data > Edit Links > Break Link, then save"). Drawings, charts, images and embeddings are ignored, never parsed.
5. **Workbook caps after parse:** at most 30 sheets, 100,000 non-empty cells, 20,000 formula cells, 500 defined names,
   formula text at most 8,192 characters (Excel's own limit); string values longer than 2,000 characters are cut and marked.
   A defined name that points outside the workbook is refused like an external link. Grid JSON at most 8 MB.
6. **Where it runs:** only in the job step `xlsx_read` (service role), never in a request. Checkpoints after scan, parse,
   engine build and diff; past **180 s** the step ends in `needs_attention` ("This workbook is too large to read in one go").
   The second lease expiry already sends a step there (Phase 2 s8). Parsing is synchronous, so the caps, not the clock,
   are what bound it; Plan Task 2 measures a generated at-cap workbook (time and heap) and lowers the caps if it passes
   60 s or 1 GB.
7. **No code from the file ever runs.** No `eval`, no custom HyperFormula functions, no HTML (`cellHTML: false`); every
   string and formula is rendered as React text. `xlsx` is imported only in one `server-only` file; HyperFormula only in
   `engine.ts` (graph test).

## 5. The pipeline (job kind `ingest_xlsx`, one step `xlsx_read`)
1. Download the object (service role), magic bytes, zip scan (s4).
2. SheetJS `read` with the s3 options; build the **grid**: per sheet, cells `[addr, f | null, v, t, z | null]` (formula text,
   Excel's cached value, type, number format), defined names, the 1904 flag.
3. Build HyperFormula from the grid (`"=" + f` for formulas, cached `v` for constants); read every formula cell's value.
4. **Diff** each formula cell, HyperFormula against Excel's cache: numbers equal within `1e-9 x max(1, |a|, |b|)`, strings
   exact, booleans exact, errors by kind. Classes: `match`; `differs`; `unsupported` (a function HyperFormula does not register,
   `#NAME?` where Excel had a value, or a cell in an array/spill range); `cycle` (`#CYCLE!`: Excel's iterative calculation);
   `no_cache` (the file has no saved value); `random` (RAND, RANDBETWEEN); `dated` (TODAY, NOW: differs by design; marked,
   not a fault). **Taint:** every cell whose precedents reach a `differs`, `unsupported`, `cycle`, `no_cache` or `random` cell,
   found by walking dependents forward from them.
5. **Suggestions (rule-based, no LLM; ADR-001 cut LLM assumption mapping):** candidate inputs are numeric constants with at
   least one formula dependent, ranked by dependents; candidate outputs are untainted numeric formula cells with no dependents,
   or with the most precedents, at most 40 each. The **sheet label** of a cell is the nearest text cell to its left in the
   same row, else above in the same column (machine-read, shown as "sheet says").
6. Write the grid, the per-cell classes and taint, the suggestions and sheet labels to Storage as one JSON
   `models/<versionId>.json` (`gridVersion: 1`); write the version's machine columns (counts, report summary, engine versions,
   `read_at`, status `ready` or `refused` with a code). Idempotent: a re-run overwrites the same object and row.

No Groq, OCR or Whisper is called; the governor is untouched and the step must never be parked with an AI wait reason.

## 6. Data model (migration `20261014000016_valuation.sql`)
- `documents.kind` += `'xlsx'`; `storage_path` pattern += `xlsx`; `jobs.kind` += `'ingest_xlsx'`; `job_steps.kind` +=
  `'xlsx_read'` (and in the admin insert policy, so "Try again" works); bucket `documents` allowed types += the XLSX type
  and `application/json` (the grid). Bucket size limit unchanged (50 MB); the 10 MB cap is the app's.
- `valuation_versions`: `id`, `company_id` fk not null, `document_id` fk unique, `version_no` (unique per company),
  `status` (`reading`, `ready`, `confirmed`, `refused`), `refusal` (code, null unless refused), `grid_path`
  (`^models/[0-9a-f-]{36}\.json$`), `sheet_count`, `cell_count`, `formula_count`, `report` jsonb (class counts, at most 200
  listed cells, unsupported function names), `engine` jsonb (`{ sheetjs, hyperformula }`), `read_at`, `confirmed_at`,
  `created_at`. Created by `start_valuation_version(p_document_id)` (admin, called from finish upload; next `version_no` for
  the document's company). Machine columns are written by `service_role` through column grants only.
- `valuation_cells` (Aksh's designations only): `id`, `version_id` fk, `sheet` (1-31 chars), `addr` (`^[A-Z]{1,3}[0-9]{1,7}$`),
  `role` (`input`, `output`), `label` (null or 1-80 chars: **his words**; null means "show the sheet label"), unique
  (`version_id`, `sheet`, `addr`). Written only by `confirm_valuation_version(p_version_id, p_cells jsonb)`; no UPDATE or
  DELETE grant: a confirmed version's cells never change. Machine text (the sheet label) is never stored here.
- `valuation_scenarios`: `id`, `version_id` fk, `name` (1-80, his), `note` (0-500, his), `created_at`, unique
  (`version_id`, `name`). `valuation_scenario_values`: (`scenario_id` fk cascade, `cell_id` fk) pk, `value` numeric (finite,
  `abs <= 1e15`). Saved only by `save_valuation_scenario(p_version_id, p_name, p_note, p_values jsonb)`, which checks every
  cell is an `input` of that confirmed version; deleted by the admin (policy). Outputs are never stored: they are recomputed.
- Functions: `start_valuation_version`, `confirm_valuation_version` (version must be `ready`; 1-40 inputs, 1-20 outputs; sets
  `confirmed`, once), `save_valuation_scenario`: admin-checked inside, security definer, `search_path = ''`, EXECUTE to
  `authenticated` only (added to the function-privileges allowlist test). RLS on all three tables with `private.is_admin()`.
- **Rule 9 in the schema:** no grant, policy, view or function gives `anon` anything on these tables; there is no
  `visibility` column, so there is nothing to flip.
- The app-level checks the SQL cannot see (it cannot read the grid): an input must be a numeric constant that is not
  date-formatted; an output must be a numeric formula cell that is not tainted. `confirmValuationAction` loads the grid
  server-side and enforces them before calling the function.

## 7. The private page
### 7.1 Where it lives
- `/desk/models`: the list (company, latest version, status, date read). No new desk tab (five already; the phone bar is
  full); reached from the inbox card ("Open model") and from a "Model" link in the item page header when the item's company
  has a confirmed version.
- `/desk/models/[versionId]`: one page, two modes by status. `ready` -> **Confirm**; `confirmed` -> **Scenarios**; `refused` ->
  the refusal sentence and "Upload a fixed workbook". A newer version shows a line "Version 4 exists: open it".

### 7.2 Confirm (before anything is computed for him)
1. **Report first:** "All 1,204 formulas give Excel's answers" or "12 formulas give a different answer from Excel; 3 results
   depend on them and cannot be chosen". A table of the listed cells: sheet!cell, Excel's value, the desk's value, reason in
   plain words ("uses a function the desk cannot compute: XIRR"; "part of a loop Excel solves by repeating: the desk cannot").
2. **Inputs:** the suggested cells, nothing pre-ticked, each with "sheet says: Cost of equity", the value, its sheet!cell, and an
   optional label field (empty; placeholder shows the sheet label). Cells he confirmed in the previous version are pre-ticked
   only if the same sheet!cell still holds a constant with the same sheet label, with a chip "used in version 3".
3. **Outputs:** the same, for the suggested results; tainted cells shown greyed with the reason, not selectable.
4. "Add a cell" by address (`DCF!C42`) or by searching sheet labels, for anything not suggested.
5. One button: "Use 4 inputs and 2 results". It writes the designations; nothing is trusted before this click.

### 7.3 Scenarios
- Header: company, "Model version 3, read 14 Oct 2026 from `<file title>`", the report chip, and a fixed line
  **"Private. Scenario outputs from your workbook; never published (rule 9)."**
- **Inputs** (left on desktop, first on phone): label (his, else sheet label marked "sheet"), workbook value, an editable
  scenario value (`inputmode="decimal"`; a %-formatted cell is edited in percent: 11.5 means 11.5%), reset per row.
- **Results** (right; on phone a sticky bar shows the first result): columns "Workbook value", "Scenario output", "Change".
  The words "target", "fair value", "intrinsic value", "upside", "price target", "buy", "sell" never appear in desk copy for this
  page (a unit test scans the module's strings). His own labels are shown as he typed them.
- **Scenario picker:** "Workbook values" (always first, read-only) and his saved scenarios; "Save as scenario" (name, optional
  note) stores the input values only. The workbook and the version are never overwritten. Delete a scenario: yes; edit: no
  (save under a new name).
- **Sensitivity grid:** one result, two inputs, 5 x 5 (3 x 3 below 480 px so the phone never scrolls sideways), around the
  current scenario; step defaults to 0.5 percentage point for %-formatted inputs, else 5% of the value; editable. Centre cell
  marked "this scenario". Tabular numerals, no colour scale, no chart.
- Numbers formatted from the cell's Excel format (`z`): %, decimals, thousands grouping; anything else as a plain number.

### 7.4 Loading and recalculation
The page is a server component that checks admin and reads the version row and designations; the calculator is a client
component loaded with `next/dynamic(..., { ssr: false })` that fetches a 10-minute signed URL for the grid JSON and then
`await import("hyperformula")`. HyperFormula runs on the main thread (a typical model has under 5,000 formulas); a Web Worker
is a later step if a real model is slow. Recalculation is HyperFormula's incremental `setCellContents`; the sensitivity grid
batches its 25 runs. No other route's client bundle may contain HyperFormula (build check in the plan).

## 9. Compliance
- Rule 9: no anon path (s6), no `(public)` route or `showcase`/`compliance` module imports `@/modules/valuation` (graph test),
  the desk layout's existing admin check and `noindex` cover `/desk/models`.
- No "copy to file" button in v1: any scenario figure Aksh wants in a case file he types into the existing (gated) editor. The
  public static, lagged scenario table is Plan 3b (needs Q27/Q28).
- The hard rule: machine output (classes, taint, suggestions, sheet labels, values) lives only in the grid JSON and the
  version's machine columns; his words (labels, scenario names and notes) and his choices (roles, input values) only in the
  three tables he writes. No field holds both.

## 10. Out of scope
The public scenario table (Plan 3b); charts beyond the sensitivity grid; a sheet-grid viewer; multi-user or client access;
`.xls`, `.xlsm`, `.xlsb`, `.ods`, Google Sheets links; more than one model per company; carrying scenarios to a new version;
editing the workbook's formulas; iterative calculation; Web Worker recalculation; LLM labelling of cells.

## 11. Allocator note
Nothing here is public, by rule. Its value to an allocator arrives later and indirectly: every public case study can say
"model version 3, read 14 Oct 2026, assumptions confirmed by the author, 1,204 formulas re-computed and matched", and
rubric R1 row 5 (each company with a model and scenario ranges) becomes true on the desk first.

## 12. Decisions (each with its cost if wrong)
| # | Decision | Cost if wrong |
|---|---|---|
| D1 | SheetJS 0.20.3 from its CDN tarball, never npm `xlsx` 0.18.5 | Low: a CDN outage fails an install; fix by vendoring the 2.4 MB tarball |
| D2 | HyperFormula 3.5.0 under `licenseKey: "gpl-v3"`, server (diff) and browser (scenarios) | Medium: needs a GPL-compatible repo licence (Q37) |
| D3 | `.xlsx` only, 10 MB, caps of s4.5 | Low: a big broker model is refused; Aksh trims sheets or caps are raised after measurement |
| D4 | External links, macros, ActiveX and data connections refused, not ignored | Low: one extra "break links, save" in Excel |
| D5 | One synchronous job step with a 180 s checkpoint, no mid-parse resume | Low: an at-cap file needs a smaller upload; measured in Task 2 |
| D6 | Grid as one JSON object in the private bucket, not rows in Postgres | Low: SQL cannot see cells, so two checks live in the action (s6) |
| D7 | Cells Aksh confirms are rows; machine data never enters them | None expected; this is the hard rule |
| D8 | Outputs depending on a mismatched, unsupported, cyclic, uncached or random cell cannot be chosen | Medium: a model with an interest loop loses some results until he breaks the loop (Q39) |
