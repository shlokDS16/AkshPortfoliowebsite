## 1. Problem
Aksh builds his valuation in Excel. Today the desk cannot hold it: the workbook lives on his laptop, its assumptions are
undated, and he cannot ask "what if the cost of capital is one point higher?" from his phone. He needs to drop the workbook
in the inbox, say which cells are his assumptions and which are the results, and then move the assumptions and see the
results move, without ever overwriting the workbook and without anything leaving the private desk.

## 2. Current state (what is reused)
- Upload: drop bar -> `startUploadAction` -> browser uploads straight to Storage with a signed upload URL (`uploadToSignedUrl`;
  the file never passes through a Vercel Function, so the 4.5 MB body limit does not apply) -> `finishUploadAction` checks
  the stored object, activates the document, queues the job's first step and schedules `after()` drain
  (`src/modules/documents/upload.ts`, `src/modules/ingestion/actions/upload.ts`).
- Jobs: `jobs` / `job_steps` with lease, passes, `needs_attention`, four pumps (Phase 2 spec s8). Trays are derived (`trays.ts`).
- Hardened zip reading: `src/lib/providers/zip-one.ts` (bounds declared and real inflated size, refuses zip64, encryption,
  odd methods; never uses entry names as paths). It reads exactly one entry; an XLSX has many, so the pattern is reused
  in a new multi-entry scanner and `zip-one.ts` is left untouched.
- Desk components: `@/components/ui/table` (`Table`, `TH numeric`, `TD`), `block-header`, `as-of`, `stat-tile`,
  `empty-state`, the inbox `document-card`, `needs-attention`. The public `scenario-table.tsx` already refuses value fields
  (rule 9) and is not touched.

## 4. Security of untrusted workbooks
The workbook is treated as hostile even though Aksh uploads it (files arrive from brokers and email).
1. **Accepted:** `.xlsx` only, at most **10 MB** (`XLSX_MAX_BYTES`). Refused at the drop bar and again on the stored object:
   `.xlsm`, `.xlsb`, `.xls`, `.ods`, `.csv`. The browser often reports an XLSX as `""` or `application/octet-stream`, so the
   client sets `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` from the extension; the job checks magic bytes.
2. **Magic bytes:** must start `50 4B 03 04`. `D0 CF 11 E0` (password-protected workbook or old `.xls`) is refused: "This
   workbook is password-protected or in the old .xls format. Save it as .xlsx without a password and upload again."
3. **Zip scan before any parser sees a byte** (`zip-scan.ts`, the `zip-one.ts` rules per entry): at most 1,000 entries; no
   zip64, split archives, encryption, or methods other than stored/deflate; each declared size at most 25 MB, the sum at most
   60 MB; every entry is really inflated with `maxOutputLength = declared size` and must match its size and CRC, so a lying
   header cannot pass (a zip bomb stops at 60 MB). Entry names are compared with fixed strings only, never used as paths.
4. **Refused parts:** `xl/vbaProject.bin`, anything under `xl/activeX/` or `xl/externalLinks/`, `xl/connections.xml`, or a
   macro-enabled content type. Messages name the Excel fix ("Data > Edit Links > Break Link, then save"). Drawings, charts,
   images and embeddings are ignored. A 1904-date workbook is refused ("Save it with the 1900 date system").
5. **Caps after the SheetJS parse, before IronCalc opens the file:** at most 30 sheets, 100,000 non-empty cells, 20,000
   formula cells, 500 defined names, formula text at most 8,192 characters; strings over 2,000 characters are cut and marked; a
   defined name that points outside the workbook is refused. The stored model object (s5.6) at most 12 MB.
6. **Server engine (native addon):** runs only inside the `xlsx_read` step (service role), never in a request. The bytes that
   passed s4.2-s4.5 are written to `os.tmpdir()` under a random name (the upload's name is never used) and deleted in `finally`.
   IronCalc is Rust (memory-safe), but a panic may end the function; that is a lease expiry, and the second expiry sends the
   step to `needs_attention` (Phase 2 s8). Checkpoints after scan, SheetJS parse, IronCalc load, evaluate and diff; past
   **180 s** the step ends in `needs_attention` ("This workbook is too large to read in one go"). Parsing and evaluation are
   synchronous, so the caps bound them; Plan Task 1 measures an at-cap workbook (time, peak RSS) and lowers the caps if it
   passes 60 s or 1 GB.
7. **Browser engine (wasm):** runs in the WebAssembly sandbox of Aksh's tab, on `/desk/models/[versionId]` only, after the
   admin check. It never sees the upload: it loads only `toBytes()` output that the server produced from a workbook that passed
   s4.2-s4.5. Memory and time are bounded by the same cell caps; Task 1 also measures one `evaluate()` of the at-cap model in
   wasm. Over 250 ms, Task 3 moves the engine into a Web Worker (otherwise main thread). The `.wasm` file is served from
   `public/vendor/` (it is the open-source engine, no data); the model bytes come through a 10-minute signed URL.
8. **No code from the file ever runs.** No `eval`, no HTML (`cellHTML: false`); every string and formula is rendered as React
   text. `xlsx` and `@ironcalc/nodejs` are imported only in `server-only` files; `@ironcalc/wasm` only in `engine-client.ts`
   and the server's `tokens.ts` (graph test).

9. **Added by Plan Task 1 (2026-10-14), after measuring; all in `src/modules/valuation/limits.ts` and `cost.ts`.**
   - Before SheetJS: each worksheet part is searched for cell tags (at most **500,000**, formatted or filled) and for any row past
     **20,000**, which is refused (`too_many_rows`) because SheetJS drops such rows without saying so; `[Content_Types].xml` and the
     workbook relationships are at most 1 MB; a VBA relationship, an `xl/macrosheets/` part or a macro content type is `macros`
     (SheetJS writes a `.bin` content-type default into every file it writes; that line alone is not a macro). Search patterns are
     length-bounded: an unbounded one took 1 s on 40,000 `<row ` openers and is quadratic.
   - After SheetJS: sheet names at most 31 characters, defined names and number formats at most 255 (Excel's own limits), and the
     size the cells will take in the stored object (12 MB) is counted while reading (`model_too_large`).
     SheetJS needs `sheetStubs: true`, or a formula with no saved value vanishes from the sheet (the `no_cache` class could never occur).
   - Before the engine: the reference graph yields an **estimate of the engine's time** (`cost.ts`); above **30 s** the read is refused
     (`too_complex`). The cell caps do not bound `evaluate()`: 20,000 formulas that each sum the same 80,000 cells took **96 s**, and a
     whole-column `SUMPRODUCT(A:A,B:B)` takes 0.4 s by itself (`MAX(A:CV)` 1.1 s). Residual: a range inside array arithmetic that sits in
     another function, such as `SUM(IF(A:A>5,B:B,0))`, is not recognised.
   - Measured at the cell caps (100,000 cells, 20,000 formulas, 80,000 constants, Node 24 on a Core Ultra 9 desktop): read 0.77 s in
     all, peak RSS about 215 MB above the test runner's own 184 MB, stored object 4.6 MB (1.3 MB of it engine bytes); wasm loads in 220 ms
     and one input change plus `evaluate()` takes 160-260 ms (the model's 20,000 formulas are re-evaluated every time), 25 changes 5 s.
     wasm 0.8.4 evaluates on every `setUserInput` unless `pauseEvaluation()` is called around the batch (the wrapper does); that halved it.
     The caps stay. Task 3 builds the Web Worker (D18): the grid alone would block a phone's main thread for many seconds at the caps.
   - IronCalc 0.8.3 cannot open a workbook with an Excel data table (What-If Analysis): `data_tables`, with the fix in the sentence.
     `INDIRECT("Sheet!A1")` with a sheet-qualified text is `#VALUE!` once imported from a file (same-sheet works), so the desk reports it as
     differing and never offers it as a result. Cells that depend on `TODAY()` differ from the saved values too, but only the `TODAY()` cell itself is
     `dated`; the cells downstream are `differs` (and so tainted). Task 3 may want to group them in the report.
   - Time zone `Asia/Kolkata`, locale `en`, language `en` are accepted by `Model.fromXlsx` (checked; `en-IN` is not a locale of the package).

10. **Added by the Task 1 review (2026-10-15).**
   - The zip scan reads the archive the way SheetJS 0.20.3 does: the local header's method, flags, checksum and sizes must equal the
     directory's (zero sizes only with a data descriptor on a deflated entry), a zip64 extra field in either header is refused, an end
     signature inside the archive comment is refused, and cell tags and rows are counted in every part (a sheet can live under any name).
     External-link and connection relationships are refused by type. Before this, a stored entry whose local header said "deflated" was
     inflated by SheetJS without a bound.
   - The reference graph reads at most **5,000,000** references (`MAX_GRAPH_REFS`), names followed at each use, so names that fan out to
     names are `too_complex` instead of a hang; functions inside a defined name count toward the engine-time estimate.

## 5. The pipeline (job kind `ingest_xlsx`, one step `xlsx_read`)
1. Download (service role), magic bytes, zip scan, refused parts (s4).
2. SheetJS `read`; caps; build the **sheet index**: per sheet, cells `[addr, f | null, v, t, z | null]` (formula text,
   Excel's saved value, type, number format), defined names.
3. IronCalc Node `fromXlsx(tmpPath, "en", "Asia/Kolkata", "en")` (locale and time zone names checked against the package in
   Task 1), `evaluate()`, read every formula cell's raw value and type.
4. **Diff**, IronCalc against Excel's saved value: numbers equal within `1e-9 x max(1, |a|, |b|)`, strings and booleans exact,
   errors by kind (type `ErrorValue`, never by string). Classes: `match`; `differs`; `unsupported` (`#N/IMPL`, or `#NAME?`
   where Excel had a value, or a cell in an array/spill range); `cycle` (`#CIRC!`: Excel's iterative calculation); `no_cache`;
   `random` (RAND, RANDBETWEEN); `dated` (TODAY, NOW: differs by design, marked, not a fault).
5. **Reference graph** (`graph.ts`, our code): each formula's references from `getTokens` (cells, ranges, sheet-qualified,
   defined names), ranges expanded within the used area. OFFSET and INDIRECT are dynamic: the cell is marked `dynamic` and its
   precedents are unknown. **Taint:** every cell reachable forward from a `differs`, `unsupported`, `cycle`, `no_cache` or
   `random` cell; a `dynamic` cell is tainted only if its own value differs.
6. **Suggestions (rules only, no LLM):** candidate inputs are numeric constants with at least one formula dependent, ranked
   by dependents; candidate outputs are untainted numeric formula cells with no dependents, or with the most precedents; at most
   40 each. The **sheet label** of a cell is the nearest text cell to its left in the row, else above in the column
   (machine-read, shown as "sheet says"). Inputs reached only through OFFSET/INDIRECT are found with "add by address".
7. **Write** one object `models/<versionId>.json` (`modelVersion: 1`): the sheet index, classes, taint, suggestions, sheet
   labels, and `engineBytes` (base64 of `toBytes()`); then the version's machine columns (counts, report summary, engine
   versions, `read_at`, status `ready` or `refused` with a code). Idempotent: a re-run overwrites the object and the row.

No Groq, OCR or Whisper is called; the governor is untouched and the step is never parked with an AI wait reason.

## 6. Data model (migration `20261014000017_valuation.sql`)
- `documents.kind` += `'xlsx'`; `storage_path` pattern += `xlsx`; `jobs.kind` += `'ingest_xlsx'`; `job_steps.kind` +=
  `'xlsx_read'` (and in the admin insert policy, so "Try again" works); bucket `documents` allowed types += the XLSX type and
  `application/json` (the model object). Bucket size limit unchanged (50 MB); the 10 MB cap is the app's.
- `valuation_versions`: `id`, `company_id` fk not null, `document_id` fk unique, `version_no` (unique per company), `status`
  (`reading`, `ready`, `confirmed`, `refused`), `refusal` (code or null), `model_path` (`^models/[0-9a-f-]{36}\.json$`),
  `sheet_count`, `cell_count`, `formula_count`, `report` jsonb (class counts, at most 200 listed cells, unimplemented function
  names), `engine` jsonb (`{ sheetjs, ironcalcNode, ironcalcWasm }`), `read_at`, `confirmed_at`, `created_at`. Created by
  `start_valuation_version(p_document_id)` (admin, from finish upload). Machine columns written by `service_role` through
  column grants only.
- `valuation_cells` (Aksh's designations only): `id`, `version_id` fk, `sheet` (1-31 chars), `addr` (`^[A-Z]{1,3}[0-9]{1,7}$`),
  `role` (`input`, `output`), `label` (null or 1-80 chars: **his words**; null means "show the sheet label"), unique
  (`version_id`, `sheet`, `addr`). Written only by `confirm_valuation_version(p_version_id, p_cells jsonb)`; no UPDATE or DELETE
  grant. Machine text (the sheet label) is never stored here.
- `valuation_scenarios`: `id`, `version_id` fk, `name` (1-80, his), `note` (0-500, his), `created_at`, unique (`version_id`,
  `name`). `valuation_scenario_values`: (`scenario_id` fk cascade, `cell_id` fk) pk, `value` numeric (finite, `abs <= 1e15`).
  Saved only by `save_valuation_scenario(p_version_id, p_name, p_note, p_values jsonb)` (every cell an `input` of that confirmed
  version); deleted by the admin (policy). Outputs are never stored; they are recomputed.
- Functions: `start_valuation_version`, `confirm_valuation_version` (version `ready`; 1-40 inputs, 1-20 outputs; once),
  `save_valuation_scenario`: admin-checked inside, security definer, `search_path = ''`, EXECUTE to `authenticated` only
  (function-privileges allowlist test). RLS on all three tables with `private.is_admin()`.
- **Rule 9 in the schema:** no grant, policy, view or function gives `anon` anything; no `visibility` column exists.
- App-level checks the SQL cannot see (it cannot read the model object): an input is a numeric constant, not date-formatted;
  an output is an untainted numeric formula cell. `confirmValuationAction` loads the model object server-side and enforces them.

## 7. The private page
### 7.1 Where it lives
- `/desk/models`: the list (company, latest version, status, date read). No new desk tab; reached from the inbox card ("Open
  model") and from a "Model" link in the item page header when the item's company has a confirmed version.
- `/desk/models/[versionId]`: one page, mode by status: `ready` -> **Confirm**; `confirmed` -> **Scenarios**; `refused` -> the
  refusal sentence and "Upload a fixed workbook". A newer version shows "Version 4 exists: open it".

### 7.2 Confirm (before anything is computed for him)
1. **Report first:** "All 1,204 formulas give Excel's answers" or "12 formulas give a different answer from Excel; 3 results
   depend on them and cannot be chosen", then sheet!cell, Excel's value, the desk's value, reason in plain words ("uses a function
   the desk cannot compute yet: CUBEVALUE"; "part of a loop Excel solves by repeating: the desk cannot").
2. **Inputs:** suggested cells, nothing pre-ticked, each with "sheet says: Cost of equity", value, sheet!cell, and an optional
   empty label field (placeholder shows the sheet label). Cells confirmed in the previous version are pre-ticked only if the same
   sheet!cell is still a constant with the same sheet label (chip "used in version 3").
3. **Outputs:** the same; tainted cells greyed with the reason, not selectable.
4. "Add a cell" by address (`DCF!C42`) or by searching sheet labels.
5. One button: "Use 4 inputs and 2 results". Nothing is trusted before this click.

### 7.3 Scenarios
- Header: company, "Model version 3, read 14 Oct 2026 from `<file title>`", the report chip, and the fixed line
  **"Private. Scenario outputs from your workbook; never published (rule 9)."**
- **Inputs** (left on desktop, first on phone): label (his, else sheet label marked "sheet"), workbook value, an editable
  scenario value (`inputmode="decimal"`; a %-formatted cell is edited in percent: 11.5 means 11.5%), reset per row.
- **Results** (right; on phone a sticky bar shows the first result): "Workbook value", "Scenario output", "Change". The words
  "target", "fair value", "intrinsic value", "upside", "price target", "buy", "sell" never appear in this page's desk copy (a unit
  test scans the module's strings). His own labels are shown as he typed them.
- **Scenario picker:** "Workbook values" (first, read-only) and his saved scenarios; "Save as scenario" (name, optional note)
  stores input values only. The workbook and the version are never overwritten. Delete: yes; edit: no (save under a new name).
- **Sensitivity grid:** one result, two inputs, 5 x 5 (3 x 3 below 480 px), around the current scenario; step 0.5 percentage
  point for %-formatted inputs, else 5% of the value; editable. Centre cell "this scenario". Tabular numerals, no colour scale.
- Numbers formatted by our `format.ts` from the cell's Excel format (`z`, from SheetJS): %, decimals, grouping; else plain.

### 7.4 Loading and recalculation
The page is a server component (admin, version row, designations, scenarios). The calculator is a client component loaded with
`next/dynamic(..., { ssr: false })`: it fetches the model object through a 10-minute signed URL, imports `@ironcalc/wasm`,
initialises it from `/vendor/ironcalc-0.8.4.wasm`, `Model.from_bytes(engineBytes, "en")`, sets the full-precision number
format on the result cells (s3), then for each change `setUserInput` per input and one `evaluate()`. The sensitivity grid runs
25 evaluations in one pass. No other route's client bundle may contain IronCalc or SheetJS (Task 3 build check).

## 9. Compliance
- Rule 9: no anon path (s6); no `(public)` route or `showcase`/`compliance` module imports `@/modules/valuation` (graph test);
  the desk layout's admin check and `noindex` cover `/desk/models`.
- No "copy to file" button in v1; the public static, lagged scenario table is Plan 3b (needs Q27/Q28).
- The hard rule: machine output (classes, taint, suggestions, sheet labels, values, engine bytes) lives only in the model object
  and the version's machine columns; his words (labels, scenario names and notes) and choices (roles, input values) only in the
  three tables he writes. No field holds both.
- Licences: permissive only (ADR-001 addendum). `THIRD_PARTY_NOTICES.md` lists SheetJS (Apache-2.0) and IronCalc
  (MIT / Apache-2.0) with their licence texts, because the wasm and its glue are served to a browser.

## 10. Out of scope
The public scenario table (Plan 3b); charts beyond the sensitivity grid; a sheet-grid viewer; multi-user or client access;
`.xls`, `.xlsm`, `.xlsb`, `.ods`, Google Sheets links; more than one model per company; carrying scenarios to a new version;
editing formulas; iterative calculation; LLM labelling of cells; 1904-date workbooks.

## 11. Allocator note
Nothing here is public, by rule. Its value to an allocator arrives later: every public case study can say "model version 3,
read 14 Oct 2026, assumptions confirmed by the author, 1,204 formulas recomputed by an independent engine and matched to Excel",
and rubric R1 row 5 (each company with a model and scenario ranges) becomes true on the desk first.
